# How Phantix works

Five steps from zero to a trusted report.

---

## 1. Register your organization

Create a Platform account. Verify identity as required (email / company modes). Invite the right people — dual-control works better with more than one trusted admin.

---

## 2. Connect your security database

Provision a **dedicated security database** for posture data. Phantix connects with credentials you control. This is where assets, findings, and risks live.

---

## 3. Inventory what you own

Add domains, applications, APIs, cloud pointers, mobile packages, and repositories.

- Prefer **Connect GitHub** (GitHub App) for repositories
- Tag crown jewels and critical systems
- Use discovery where entitled

---

## 4. Assess with permission

Run scoped scans or launch a VAPT campaign. Sensitive steps can require approval. Tools run under your entitlements and your defined scope.

**You authorize. Phantix executes within policy.**

---

## 5. Prove and fix

- Findings pass a **verification** mindset before executive collation
- **Impact analysis** frames business and technical consequence
- Export JSON for automation or PDF packages for leadership (plan-dependent)
- Track remediation ownership
- Alert channels keep the right people informed

---

## Optional: AI specialists on demand

When you need help triaging, writing up findings, or explaining compliance gaps, invoke a **domain agent** (SOC, GRC, VAPT, threat intel, assets). Agents call the same engines you use — they don’t replace them.

---

## Day-2 operations

| Rhythm | Action |
|--------|--------|
| Weekly | Review new assets and open risks |
| Per release | Scoped scan or campaign on changed surface |
| Monthly | Board pack / tracker review |
| Continuous | Dual-control for sensitive tests; audit trail on |

---

## Time to first value

Many teams can:

1. Register
2. Connect a security DB
3. Add a domain or public GitHub repo
4. Run a light assessment
5. Export a first report

within a guided session — then expand scope as trust grows.
